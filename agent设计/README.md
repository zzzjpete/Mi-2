# Agentic RAG 顶层架构设计

> 本目录只出设计，不含实现。未修改任何现有代码，未新增任何可执行文件。

把现有的单轮 RAG 流水线扩展成一个「规划 → 执行 → 反思 → 整合」的闭环 Agent，
同时保留原有链路作为默认模式，两种模式共用一套响应结构与运维设施。

## 一、设计原则

从现有系统往外推，不从零设计。六个组件里五个已有对应实现，接口照着现有签名写，
而不是照着「一个 Agent 应该长什么样」写。这样出来的接口是能落地的。

不做通用 Agent。这个 Agent 长在一个具体系统上，下面几条是现有系统已经付出代价
换来的，设计中全部保留：

| 现有约束 | 在 Agent 设计里的落点 |
|---|---|
| 三态拒答语义（完全拒答 / 部分作答 / 正常作答） | 只在最终整合后判定一次，Agent 提供期望值但不覆盖判定（[01 · 五](01_核心架构.md)） |
| `[S#]` 出处号与引用校验（used / available / fabricated） | 全局编号分配器，编号绑定 `chunk_id`、一经分配永不变更（[01 · 三](01_核心架构.md)） |
| 确定性修正优先于模型修正 | 反思环节沿用 `enforce()` 的既有顺序，不新设计（[02 · 五](02_组件接口.md)） |
| 证据适用性判断（人群 / 终点匹配） | **放在每轮反思内**，不放最终整合（[01 · 四](01_核心架构.md)） |
| 全离线 | 工具层只注册本地工具，无外部 API（[02 · 二](02_组件接口.md)） |

判定由代码给，不由 Agent 自称。现有系统的一条既定原则（「提示词只能提高遵守率，
判定必须由代码给」）在 Agent 模式下继续成立：Agent 可以报告「我认为证据充足」，
但合规与否仍由 `FormatChecker` 判。

## 三、四个关键决策（已定）

有四处选择会直接改变流程图与状态机。

### 1. State 用追加式，不用可变对象

`rounds: List[RoundSnapshot]` 只追加不改写；`evidence_pool: Dict[chunk_id, ...]` 共享可变。
因为可变 State 一旦被第 3 轮改写，「第 2 轮当时看到什么、为什么决定补检索」就永远答不出来，
而可复现性是这个系统的核心资产。大件是检索结果，各轮只存 `chunk_id` 引用，内存代价可控。

### 2. 完整校验只在最终整合后跑，每轮跑证据侧子集

`check()` 的三态判定、章节完整性、参考文献完整性都是针对最终答案定义的。
中间轮次没有「## 参考文献」一节，跑完整校验会得到一堆必然违规——
**拿终态判据去量中间态，测出来的是判据的错配**，不是系统的问题。

每轮子集三项，均不依赖章节结构：引用编号越界、数字未溯源、证据适用性。

第三项是刻意加的：它恰恰属于「整合后修不了」的那一类。发现 HFrEF 试验的数据被用在
HFpEF 问题上时，整合阶段能做的只有删掉那句话，而正确动作是回去补检索——
那必须在轮内发现。这条也把 P3（人群/终点匹配校验）接进了 Agent 设计，不另起炉灶。

### 3. 反思器可以回到规划，全局 1 次

只能补检索不够。用户问「A 与 B 哪个更好」，若检索发现 B 这个试验根本不存在，
补检索毫无意义——补多少次都查不到不存在的东西，正确动作是重新规划成「指出前提错误」。
这也补上现有系统的一个短板：虚构试验类问题目前的行为是正确拒答，
但**能拒答 ≠ 能纠正错误前提**。

**闸门写死**：全局至多 1 次；重规划请求必须携带「上次规划为什么失败」的结构化证据；
第二次仍失败则直接进整合，按现有规矩拒答。

### 4. 子任务失败分三类处置，工具返回必须三态

这条展开写，因为三类失败在返回值上很容易长成同一个样子。

| 失败类型 | 处置 | 理由 |
|---|---|---|
| 工具异常（检索器崩了） | 重试 1 次，仍失败则整体失败，返 5xxx | 系统故障，不是「没有证据」 |
| 检索为空（查了但没结果） | 跳过继续，标记该子任务无证据 | 这是信息，最终映射到 `partial` |
| 证据不适用（人群/终点不匹配） | 跳过继续，标记原因 | 同上 |

前两类的区分是整条设计里最容易被做丢的一处。检索器崩了返回空列表、库里真没有也返回空列表，
调用方无从分辨——于是反思器看到空结果就判「信息不足，补检索」，
而实际是工具挂了，补多少次都是空，直接烧完最大轮次。
单轮系统里这个混淆只是答得差；Agent 模式里它会让整条推理链走错方向。

所以这不是约定而是接口契约：工具返回结构必须显式区分 `failed` / `empty` / `ok` 三态，
**不许用空列表兼表「失败」与「查了但没有」**。

第三类与前两类的差别在于它有信息量。「找到了，但不适用于你问的人群」是可以告诉用户的，
所以它映射到部分作答而不是拒答——问 HFpEF 检索到 HFrEF 试验时，
正确回答是「HFrEF 人群有此数据，但不能外推」，不是「无法回答」。

这三条与三态拒答同源：**空不等于没有，失败不等于空。**

## 四、未定项

规划器没有天然收敛点，以下明确列为本轮不做，避免无限细化：

- 拆解策略只定义三种（事实型 / 比较型 / 时序因果型）及其判据，不穷举医学问题类型。
  更多类型（剂量计算、鉴别诊断、指南比对等）留待有真实用例时再加。
- 子任务优先级只区分「并行 / 串行」，不做更细的权重排序。
- 工具层只注册现有两个工具（多路检索、查询理解），不设计尚不存在的工具
  （如结构化数据库查询、计算器）。
- 规划器的模型选型不定：沿用 `qwen3:8b` 还是换更小的模型做意图分类，
  要等有真实用例后量过才能决定。
- 不设计评测方案。Agent 模式的效果怎么量是独立课题；现有 golden 集只测检索、
  已降级为回归集，不能用来宣称 Agent 提升了多少。
