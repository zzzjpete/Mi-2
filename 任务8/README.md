## 二、数据流

```
检索快照（阶段七固化）
      │
      ├─ 趟 1 串行 ┐
      ├─ 趟 2 并行 ┼─ ParallelBatchProcessor ─▶ 每线程一条 MedicalGenerationPipeline
      └─ 趟 3 并行 ┘        （顺序保持 / 错误隔离）        │
                                                      ├─ CachedLLMGenerator ─▶ 阶段级缓存（只收温度 0 的 ①③）
                                                      └─ 四段链 ─▶ 答案
                                                              │
        流水线级缓存（键 = 查询 + 检索证据指纹）◀────────────────┘
                                                              ▼
                                              AnswerEvaluator（并行，纯 CPU）
                                              ① ROUGE  ② 关键信息召回  ③ 幻觉信号  ④ 可读性
```

**两级缓存各管一段**：阶段级挡的是「同一段提示词又问了一遍」（只对温度 0 的 ①③ 生效）；
流水线级挡的是「同一个问题配同一批证据又跑了一遍」。前者细、命中率低但安全；
后者粗、命中即省整轮，代价是要接受把一次抽样固定下来。

## 三、实测结果（2026-08-03，四道验收错题）

### 1) 批量处理：串行 vs 并行（两趟都清空缓存，起跑线相同）

| 趟 | 并发 | 墙钟 | 成功 |
|---|---|---|---|
| 串行（冷） | 1 | 144.53 s | 4/4 |
| 并行（冷） | 4 | **106.37 s** | 4/4 |
| 并行（热，走缓存） | 4 | **0.002 s** | 4/4 |

**并行只换来 1.36×，不是 4×**——这是本阶段最该说清楚的一个数字。原因不在线程池，在于
本机是**单卡 + 单个 Ollama 进程**：多个请求争同一份权重和同一块 GPU，服务端会排队。
对照组：同样的线程池跑纯 I/O 等待任务，4 线程实测 **3.98×**（见验证 F 组）。
**结论是"并行对本地生成的收益受单卡限制"，不是"多线程没用"**——评估、分词、正则这类
纯 CPU 批量照样吃得到并行收益（本轮 8 份答案的四维评估并发跑完只用 0.05 s）。

### 2) 缓存

| 项 | 实测 |
|---|---|
| 冷 → 热 墙钟 | 106.37 s → **0.002 s** |
| 命中数 | **4/4** |
| 缓存替下来的模型时间 | **360.8 s**（四题合计） |
| 命中返回的答案与首次**逐字相同** | **4/4** |

| 流水线级缓存（门限 0.3） | 4 条，命中率 1.0 |

### 3) 答案评估（参照 = 该题检索到的证据原文）

| 用例 | ROUGE-L f | 关键信息召回 | 幻觉风险 | 可读性 | 均句长 | 中英混排 |
|---|---|---|---|---|---|---|
| live-1 ① 编造参考文献 | 0.1242 | 0.3158 | 0.2331（低） | 0.7246 | 68.2 | 0.41 |
| live-2 ② 药名张冠李戴 | 0.1468 | 0.1944 | 0.0000 | 0.6798 | 76.9 | 0.39 |
| live-3 ③ 药物分类错误 | 0.1577 | 0.2258 | 0.0000 | 0.7022 | 77.1 | 0.38 |
| live-4 ④ 时间线矛盾 | 0.1526 | 0.2258 | 0.0000 | 0.6729 | 80.1 | 0.40 |
| **均值** | **0.1453** | **0.2405** | **0.0583** | **0.6949** | **75.6** | **0.394** |

**这四列各说明什么，必须分开读**：

- **ROUGE-L 0.145 不是"答得差"**。参照是英文证据原文、答案是中英混排的结构化 Markdown，
  词面本来就不该高度重合；这个数字**只能用来横向比较**（比如 RAG vs 裸模型），
  不能当作绝对质量分。
- **关键信息召回 0.24** 的含义是：证据里的百分比/剂量/时间/安全性等硬信息，答案覆盖了约四分之一。
  低是正常的——答案是**摘要**，不是复述，证据里 10 条文献的全部数字不可能都进 5 段话。
  真正有用的是**分项**：live-1 的 `percentage=0/5`、live-4 的 `statistic=0/5` 说明
  **数字类信息是最容易被摘掉的一类**，这条可以直接回去改提示词。
- **幻觉风险几乎全 0**：四道题共命中信号 1 条（live-1 的「研究表明」类措辞），
  其余答案连信号都没有。对照裸模型：同样的尺子量出 1 条无出处信号、风险 0.0437。
  ⚠ **别把这条当成"RAG 不幻觉"的证据**——它量的是措辞，不是事实。
- **中英混排 0.394**：约四成句子的语言与该答案的主语言不一致。这正是阶段七
  「答案会中英混排」那条已知缺陷，现在**第一次有了数字**，可以拿来判断改提示词有没有效果。

### 4) 同一把尺子量裸模型（复用阶段七已存的答案，未额外调模型）

| | ROUGE-L f | 关键信息召回 | 幻觉风险 | 无出处信号 | 可读性 |
|---|---|---|---|---|---|
| **RAG** | **0.1453** | **0.2405** | 0.0583 | 1 | 0.6949 |
| 裸模型 | 0.1219 | 0.0846 | 0.0437 | 1 | 0.8096 |

**关键信息召回 0.2405 vs 0.0846（2.8 倍）是这张表里最有信息量的一格**：同一批证据里的
剂量、百分比、时间、安全性信息，RAG 能落回来的是裸模型的近三倍——裸模型压根看不到这些证据。

⚠ **口径必须一起写**：这两列都是**对同一批检索证据**算的，RAG 看得见、裸模型看不见，
所以 RAG 更高是**结构性的，不是"更聪明"**。它量的是「有没有贴着证据写」，不是「谁答得更对」。
另外裸模型的可读性反而更高（0.8096 vs 0.6949）——它的答案更短、句子更整齐、语言更一致；
**可读性高低与可信度无关**，这一格恰好说明为什么四个维度不能加总成一个分。

## 四、这一阶段踩到的坑（都是实测撞出来的，不是预防性设计）

**1. `rouge` 库直接吃中文，分数几乎没有意义。** 它按空白切词，一整句中文会被切成 **1 个"词"**。
实测：两句高度相似的中文，不预分词 ROUGE-L = **0.0000**，按「中文按字、英文按词」预分词后 = **0.7907**。

**2. `rouge` 把 `.` 当句子分隔符，而医学答案满是小数。** `0.45`、`p<0.001` 会被劈成两个"句子"，
既污染 unigram 计数，也让 ROUGE-L 走错分支。**发现方式**：自带实现与库在真实答案上对不上，
最大差值 0.26。解法是 token 内的小数点换成 `·`，`.` 只留作真正的句子边界。

**3. 把整段当一个句子喂给 `rouge`，直接 `RecursionError`。** 它的 LCS 回溯是**递归**的，
2000+ token 的真实答案直接栈溢出。修好第 2 条之后立刻撞上这条——因为小数点没了，
整段变成了一个超长句。给它真正的句子边界即可，而且句子级切分本来就是 ROUGE-L summary level 的正确用法。
（`rouge_scores` 里仍然捕获 `RecursionError` 并降级到自带实现，作为兜底。）

**4. 跨语种的关键信息比对，按字面永远匹配不上。** 证据是英文、答案常是中文：
「不良反应」与 `adverse events` 字面无交集，安全/建议/机制三类的召回率会**恒等于 0**。
那不是模型漏了信息，**是尺子坏了**。解法：这三类走概念表，中英同义写法映射到同一 concept id。

**5. 风险分用「除以上限再截断」会失去单调性。** 实测 110 字的文本里 1 个信号和 4 个信号
**都顶到 1.0**，完全分不出轻重。改成 `risk = 1 − exp(−密度/2)`：恒在 [0,1) 且严格单调，
信号每多一个分数一定上升，只是越往上升得越慢。

**6.（最隐蔽的一个）`cache or GenerationCache(...)` 会把传进来的缓存悄悄丢掉。**
`GenerationCache` 定义了 `__len__`，**空缓存的布尔值是 `False`**，于是 `or` 走了右分支、
新建了一个缓存。表现极其隐蔽：包装器照样能命中（用的是它自己新建的那个），但调用方设的
TTL / 容量 / 温度门限**全部失效**，统计永远是 0。
**是怎么发现的**：`评估_跑测试集.py` 的判定打出「写入 **0** 条，却因高温跳过 **16** 次」——
这两个数在同一个对象上不可能同时成立。已改成 `cache if cache is not None else …`，
并给 `GenerationCache` 加了 `__bool__` 恒真，验证里补了一条同一性断言（G 组第 2 条）。

## 五、关键设计取舍

**1. 为什么四个维度不合成一个总分。** 它们量的不是一回事：ROUGE 高可能只是照抄证据；
可读性高可能只是答得短而整齐（裸模型那一格就是活例）。合成总分会把这些互相冲突的信号
搅成一个没法解释的数，出了问题也定位不回去。所以只给四个独立的数 + 分项明细。

**2. 幻觉检测为什么区分「有出处」与「无出处」。** 「研究表明[S3]」和光秃秃的「研究表明」
完全是两回事，而后者正是整个 RAG 系统要消灭的东西。同句带 `[S#]`/PMID/DOI 的信号记为
`mitigated`，默认不计入风险，但**仍然列出来**供人核。想更严就开 `count_cited_as_signal=True`。

**3. 缓存键为什么把整段提示词都算进去。** `CachedLLMGenerator` 直接把完整 messages
（含 system 提示词）纳入键材料。这样**改了提示词模板，键自动就变了**，不可能读到旧答案——
这类 bug 一旦发生极难察觉（答案看起来是新的，其实是上一版提示词的产物）。

**4. 只缓存成功的结果。** 失败结果（连接断、JSON 解析不出）缓存下来等于把一次故障
钉死成永久答案。`json_output=True` 时还要求 `json_ok` 才写。

**5. 默认温度门限 0.0，流水线级演示时才显式抬到 0.3。** 温度 > 0 的输出本来就不确定，
缓存它等于**把一次抽样固定下来**：复跑评测时看起来"稳定"，其实是假的稳定。
所以这必须是调用方**明确知情后**才打开的开关，而不是默认行为。脚本里也会把这句话打出来。

**6. `get_or_compute` 刻意不在计算期间持锁。** 一次生成要几十秒，持锁会把并发批量卡成串行。
代价是同一个键可能被并发算两次（结果相同，都写入）。对生成这种纯函数式调用，
这是划算的取舍：多花一次算力，换不阻塞。

**7. 批量按线程而不是进程。** 本项目批量的瓶颈是模型推理与 HTTP 等待，不是 Python 计算；
线程池够用且能共享缓存对象。纯 CPU 密集要吃满多核得用多进程——验证 F 组里保留了
GIL 影响的实测对照（`生成_批量处理.py --benchmark`）。

## 八、已知局限与下一步

**局限（如实说明）**

1. **量到的仍是「贴不贴着证据」，不是「对不对」。** 没有人工标准答案，`reference_kind` 只能是
   `evidence`。评估器已支持 `--refs` 传 gold，缺的只是那份标注。
2. **幻觉检测是措辞层面的启发式。** 措辞谨慎的编造它抓不到；抓到的也只说明「说得太满且没给出处」。
3. **刻度都是约定值。** 句长经验带 15~45 字、风险密度尺度 2.0、长句阈值 80 字，都没经过人评校准。
4. **ROUGE 对中英混排答案天然偏低。** 答案是中英混排的结构化 Markdown、参照是英文证据原文，
   词面重合本来就低。只能横向比，不能当绝对分。
5. **并行收益受单卡限制**（1.36×），且这个数字随 Ollama 的 `OLLAMA_NUM_PARALLEL` 与显存而变。
6. **关键信息召回的分母偏大**：证据里 10 篇文献的全部数字都算进 `gt_matches`，
   而答案只是摘要。所以绝对值天然低，**分项**比总分有用。

**下一步**

1. **建人工标注小评测集**（阶段五~八共同的遗留）：一旦有 gold，本阶段的评估器不用改一行代码，
   `--refs` 传进去，口径自动从 `evidence` 升级为 `gold`，`recall = overlap / gt_matches` 才是
   任务书的本意。
2. **拿分项指标去改提示词**：`percentage` 与 `statistic` 两类召回明显偏低（live-1 的 0/5、
   live-4 的 0/5），说明数字类证据最容易被摘掉；中英混排 0.394 也可以直接当作改提示词的靶子。
   **这是本阶段第一次让"改提示词有没有效果"变成可测量的事。**
3. **把评估器接进消融对照**：阶段七的消融只量化了成本侧（4.99× 耗时），
   "四段链是否更忠于证据"没数据；现在有了统一的尺子，可以先看三种链路配置在
   关键信息召回与幻觉信号上的差别（仍不能替代人工标注，但比没有强）。
