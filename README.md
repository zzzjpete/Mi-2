# 医学专业知识 RAG 系统

让本地大模型回答医学问题时，先从 PubMed 文献检索证据，再据此作答并给出出处。
减少幻觉、可溯源、全程离线

| | |
|---|---|
| 语料 | PubMed PMC oa_comm 子集，快照 `baseline 2026-06-18`，11 包 / 76 GB JATS XML / 400.06 万篇 |
| 索引 | 按块分层抽样入库 399.8 万块，覆盖 227.4 万篇（平均每篇 1.76 块，非完整入库）｜768 维余弦向量 + 同规模 BM25 |
| 模型 | 本地 `qwen3:8b`（Ollama，Q4_K_M，100% GPU）｜嵌入与重排用 BAAI bge 三件套 |
| 服务 | FastAPI，18 个接口，同步问答 + SSE 流式，验证 229/229 |
| 代码 | `scripts/` 下 79 个脚本，单一来源；11 个可独立发出的阶段交付包 |

---

## 一、要解决什么

裸模型直接回答医学问题时，可能会留下四类典型错误，它们也是本系统的验收靶子：

| 错误类型 | 具体表现 |
|---|---|
| 编造参考文献 | 给出的标题 / 期刊 / 卷页全部查无此文 |
| 罕见病药名张冠李戴 | 法布里病的酶替代治疗药名答成别的品牌名 |
| 药物分类错误 | 多发性硬化：单抗 / S1P 调节剂 / 干扰素互相混淆 |
| 时间线自相矛盾 | 阿尔茨海默新药的获批时间前后打架 |

接 RAG 之后：出处可溯源 22/22（裸模型 0/18），关键信息召回 0.2405 vs 0.0846（2.8×）。

⚠ 口径：这两个数量的是**可验证性与贴合度，不是临床正确性**。措辞谨慎的事实错误、
临床判断错误，本系统的自动指标测不到。

## 二、架构与数据流

```
PMC oa_comm   76 GB JATS XML · 400.06 万篇原文
     │  ① 解析与切块          结构感知切分，保住分节标签与 PMCID
     ▼
9,243 万文本块                512 token / 64 overlap
     │  ② 按块分层抽样 4.33% + 向量化
     ▼
┌────────────────────────┬───────────────────────┐
│ Chroma  399.8 万 × 768  │ BM25  399.8 万块       │   两条召回腿
└───────────┬────────────┴───────────┬───────────┘
            │                        │
用户提问 ─ ③ 查询理解 ─▶ 中译英 / 实体识别 / 同义词扩展 / 过滤条件
            │
            ▼  ④ 多路召回 → 融合（RRF / 加权 / 简单）
            ▼  ⑤ 多准则重排：相关性主序，时效性同分裁决，landmark 有条件保底
            ▼  ⑥ 上下文组装：去重 / 来源多样性 / token 预算 / 打 [S#] 出处号
            ▼  ⑦ 四段生成链：证据评估 → 作答 → 批判审查 → 定稿
            ▼  ⑧ 强约束层：硬约束提示 + 输出骨架 + 生成后校验与确定性修正
            ▼  ⑨ HTTP 服务：同步 /qa/ask · 流式 SSE /qa/stream · 会话 / 统计 / 文档管理
     带出处、可溯源的回答
```

每一环做什么、为什么这么设计，见 [`docs/架构说明.md`](docs/架构说明.md)。
那些反直觉的决定（为什么重排池是 50、为什么时效性不进加权和、为什么文献目录不走
Chroma）连同依据数字，见 [`docs/工程笔记.md`](docs/工程笔记.md)。

## 三、快速开始

```powershell
$py = "E:\rag\conda\envs\medrag\python.exe"      # 系统 PATH 上的 python 是 3.14，缺依赖
$env:PYTHONIOENCODING = "utf-8"
$env:OLLAMA_MODELS    = "E:\rag\ollama\models"   # 启动 Ollama

# 1) 启动服务（默认快照证据，不加载 65GB 向量库）
& $py scripts\服务_应用.py --port 8000           # 交互式文档 http://127.0.0.1:8000/docs

# 2) 终端问答（另开一个窗口）
& $py scripts\服务_终端客户端.py --fast

# 3) 离线验证（224 项，约 4 秒，不需要 Ollama、不需要向量库）
& $py scripts\服务_验证.py
```

接真库检索（需要 65 GB 向量库 + 3.4 GB BM25 索引，约 15.8 GB 内存，加载约 70 秒）：

```powershell
& $py scripts\服务_应用.py --port 8000 --mode live --warmup --translate llm
```

> ⚠ live 模式问中文，`--translate llm` 不是可选项。默认中译英走一份几百条的手写词典，
> 词表外的病名药名会被整词丢弃：问「法布里病有哪些酶替代治疗药物」只剩一个 `treatment`
> 去查全库，检索回来的是蝴蝶名录。**这类错和「库里真没有证据」在响应体里长得一模一样**，
> 所以真正发出去的英文检索式会经 `retrieval_query` 回显给调用方。

装环境、重建索引、运维与故障排查，见 [`docs/部署与运行.md`](docs/部署与运行.md)。

## 四、核心能力

- 混合检索：向量 + BM25 双路召回，三种融合可切；重排以相关性为主序，时效性只做同分裁决。
- 证据受限生成：四段链的每个结论都带 `[S#]` 出处号，编号越界与编造文献由代码查出，
  不靠模型自觉。
- 拒答而不是硬答：超出知识库边界、证据年份晚于问题所问年份时强制拒答，
  并区分「完全拒答 / 部分作答 / 正常作答」三态。
- 格式与术语强约束：必需章节、缩写首次给全称、参考文献完整性由校验器判定，可自动修正。
- 服务化：21 个错误码分五族，日志每行带 `request_id`，存活与就绪两个探针分开，
  调用记录落库供成功率 / 拒答率 / p50 / p95 统计。
- 全离线：除构建 landmark 集合时一次性取 10 个 PMID 的摘要外，运行期不发出任何网络请求。

## 五、评估结果

三组指标口径不同，各自独立，不合成一个总分。完整表格与口径说明见
[`reports/README.md`](reports/README.md)。

**检索**（golden 集 235 条，只跑检索、零方差）——分三层报，不合成总体：
T1 纯中文临床 151 条 `R@10 = 0.483`，T2 术语直穿 49 条 `0.673`，T3 标识符锚定 35 条 `0.829`。
这把尺子测出并修好了一个真问题：多准则重排原本在净伤害检索，T1 R@10 从 0.417 升到 0.497。

**生成约束**（13 道五类对抗题，基线 → 约束 + 校验修正）：
拒答率 `0 → 1.0`（应拒的 9 道），幻觉率 `0.6923 → 0`，术语合规率 `0.4615 → 1.0`。
代价是 prompt token +40%，墙钟基本不变。

**服务**：离线 224 项（4.1 秒，不需要 Ollama）+ 真起 uvicorn 与真模型的端到端 5 项。
最有信息的一格是：出处清单 0.03 秒就推给客户端，首个答案字要 7.7~8.0 秒，
可见流式在这里的价值不是逐字打印，是把等待期填上真实信息。

外部黑盒评测发现的问题与改进优先级，见 [`docs/medrag_改进任务清单.md`](docs/medrag_改进任务清单.md)。

⚠ 两条必须一起知道的口径：幻觉率与拒答率在那一轮高度共线（9 次幻觉命中全部是「该拒未拒」）；
golden 集已进公开仓库，**只剩回归集资格**，可以说「回归通过」，不能说「提升了多少」。

每个 `任务N/` 是一份自包含交付包（说明 + 任务书 + 验证报告 + `脚本/` 下的全部代码副本），
**单独发出去也能独立跑起来**；包内脚本由 `scripts/校验交付包.py` 按 MD5 单向同步。
逐个脚本的说明见 [`docs/模块索引.md`](docs/模块索引.md)。

⚠ `scripts/` 不分子目录、不改文件名：脚本之间按同目录文件名动态加载（111 处），
另有 11 个交付包内的 106 份副本受 MD5 校验。

> 数十 GB 本地大件已由 `.gitignore` 排除、均可由 `scripts/` 重建：`conda/`、
> `data/`（切块产物 / 向量库 / BM25 索引 / 词典 / 文献目录）、`hf-cache/`、
> `ollama/`、`report_data/`、`logs/`。

## 七、环境与依赖

conda 环境 `medrag`（Python 3.11，conda-forge）+ PyTorch 2.6.0+cu124；
关键依赖 chromadb / transformers / bm25s + PyStemmer + scipy（BM25 那条腿）/ pyarrow / rouge；
本地模型 Ollama `qwen3:8b` 与 bge 三件套。完整清单见 [`requirements.txt`](requirements.txt)，
安装与先决条件见 [`docs/部署与运行.md`](docs/部署与运行.md)。

项目根由 `scripts/_medrag_root.py` 解析（`MEDRAG_ROOT` → 上溯找标志目录 → 兜底），
仓库可以搬到别的盘或别的机器上跑，代码不用改。
环境铁律（解释器、`HF_HOME`、导入顺序、编码）见 [`docs/工程笔记.md`](docs/工程笔记.md) 第一节。
