# 评估与日志报告 · 总索引

这个项目的每一个对外说法都有一份可打开的原始输出撑着。这份索引回答三个问题：
**哪份报告在哪、它是什么、怎么重新生成它。**

三条约定：

- **本索引里的每一份都在仓库里，点开就能看**。只在本机、不进仓库的产物集中列在
  [第五节](#五-只在本机的产物不进仓库)，并明确标注。
- **`report_data/*.txt` 是验证脚本的原始输出，属证据链，只读不改**。
- **报告有防降级保护**：弱运行不许覆盖强运行的报告，见
  [`../docs/工程笔记.md`](../docs/工程笔记.md) 二·8。

## 七、验证夹具（`reports/fixtures/`）

几个验证脚本坚持用**真实产物**做断言，而不是手编的小例子。这些产物原本只在
`report_data/`（整目录不进 git），于是 clone 下来的仓库跑不出报告里那几个数。
实测过：约束验证 99 → 95、评估验证 66 → 65（两者都如实写明跳过），
**服务验证直接崩在解引用上**。所以这三份随仓库带：

| 夹具 | 谁在用 | 大小 |
|---|---|---|
| `fixtures/检索快照_live.json` | 服务_验证 / 约束_验证 / 评估_验证 | 103 KB |
| `fixtures/评估_测试集.jsonl` | 约束_验证 | 58 KB |
| `fixtures/生成_流水线测试_live.jsonl` | 评估_验证 | 57 KB |

解析顺序由 `scripts/_medrag_root.py::evidence_path()` 决定：
**`report_data/` 优先**（本机跑过就用本机最新那份）→ 回退 `reports/fixtures/`（仓库冻结副本）
→ 都没有则让调用方原有的「缺文件就跳过」逻辑生效。

带上它们之后，**224 / 99 / 66 这三个数在一个干净 clone 上可以复现**（实测）。
