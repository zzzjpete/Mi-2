## 〇、先决条件

| 项 | 值 |
|---|---|
| 硬件 | GPU ≥ 10 GB 显存、内存 ≥ 32 GB、磁盘 ≥ 200 GB（原始数据 76 GB + 索引 69 GB + 中间产物） |
| Python | conda 环境 `medrag`，Python 3.11（conda-forge） |
| 模型运行时 | Ollama ≥ 0.9，模型 `qwen3:8b` |
| 模型权重 | `bge-base-en-v1.5`、`bge-reranker-base`、`bge-m3`，缓存在 `hf-cache/` |

```powershell
$py = "E:\rag\conda\envs\medrag\python.exe"      # ⚠ 不要用 PATH 上的 python（3.14，缺依赖）
$env:PYTHONIOENCODING = "utf-8"
$env:OLLAMA_MODELS    = "E:\rag\ollama\models"   # 起 Ollama 前必须设
ollama serve                                      # 另开一个窗口常驻
```

依赖装法：`pip install -r requirements.txt`。
⚠ 这份清单里 **`bm25s` / `PyStemmer` / `scipy` 是 BM25 那条腿的核心**——
缺了它们服务照样起得来，只是**多路融合少一路而不报错，结果静默变差**。

**项目根不必是 `E:\rag`**。路径由 `scripts/_medrag_root.py` 解析：
`MEDRAG_ROOT` 环境变量 → 从脚本位置上溯找标志目录 → 兜底。
整个仓库可以搬到别的盘或别的机器上跑，代码不用改。

## 一、重建索引（每台机器做一次）

⚠ **建库与建索引这类多小时任务要在自己的终端窗口里跑**，不要放进会被回收的后台
（本项目因此杀坏过一次向量库，见 [工程笔记 一·9](工程笔记.md)）。

### 完整重建链

| 步 | 命令 | 产物 | 耗时 |
|---|---|---|---|
| 1 | `bash scripts/下载数据.sh` | `data/pubmed/`，76 GB | 取决于带宽 |
| 2 | `& $py scripts\切块_主管线.py --all --workers 12` | `data/chunks/`，9,243 万块，42 GB | **9~10 小时** |
| 3 | `& $py scripts\切块_质量校验.py` | 切块统计与抽样校验 | 分钟级 |
| 4 | `& $py scripts\向量化_建库.py` | 抽样子集 + 向量库 | 数小时 |
| 5 | `& $py scripts\检索_构建BM25索引.py --full` | `data/bm25_index_4m/`，3.4 GB | **约 13 分钟** |
| 6 | `& $py scripts\检索_构建同义词词典.py` | `data/dict/mesh_synonyms.json`，9.5 MB | 分钟级 |
| 7 | `& $py scripts\检索_扫描元数据分布.py` | `data/dict/corpus_meta.json` | 分钟级 |
| 8 | `& $py scripts\生成_分词器.py --rebuild` | `data/tokenizer/qwen3_tokenizer.json` | 秒级 |
| 9 | `& $py scripts\服务_文档目录.py --build` | `data/docs_catalog.db`，1.0 GB | **45 秒** |

### 已有 `merged_4m.parquet` 时的快路

`data/vectors/merged_4m.parquet`（15 GB，向量 + 正文 + 元数据合并表）是**建库保险文件**。
有它就不必重跑第 1~4 步，也不需要 GPU：

```powershell
& $py scripts\恢复_重建库.py          # 约 4.5 小时，不重嵌入
```

这个文件是阶段四向量库损坏后恢复出来的，此后一切重建都以它为输入。**不要删。**

### 可选：landmark 补充集合

10 篇关键 RCT / 指南不在 oa_comm 开放子集里，单独建一个小 collection 补上：

```powershell
& $py scripts\landmark_构建集合.py --fetch    # ⚠ 全项目唯一一次联网（10 个 PMID，0.5 秒）
& $py scripts\landmark_构建集合.py --build    # 离线建库，不碰 65GB 主库
```

> **联网边界**：**构建期一次性联网**取摘要，**运行期仍全离线**。
> 条目落盘后重建 collection 不需要再联网，**跑服务的人永远不需要联网**。
> 发出去的只有 PMID，没有任何本机数据。详见 [工程笔记 二·10](工程笔记.md)。

不建也能跑，只是少了这 10 篇的保底。

## 二、起服务

```powershell
Copy-Item .env.example .env        # 按需改；.env 不进仓库（可能含 API Key）

# A. 开发 / 演示：快照证据，不加载 65GB 向量库，秒级启动
& $py scripts\服务_应用.py --port 8000

# B. 真检索：需要 65GB 向量库 + 3.4GB BM25 索引 + 约 15.8GB 内存，加载约 70 秒
& $py scripts\服务_应用.py --port 8000 --mode live --warmup --translate llm

# 不起服务，只看接口清单
& $py scripts\服务_应用.py --print-routes
```

交互式文档：`http://127.0.0.1:8000/docs`

**两个参数不是可选的**（B 模式下）：

- `--translate llm`——不加就是在碰运气。默认中译英走一份几百条的手写词典，
  词表外的病名药名**整词丢弃**，检索完全跑偏，而响应体和「库里真没有证据」长得一模一样。
- `--warmup`——**预热必须连模型一起预热**。live 模式下第一个 LLM 调用是中译英，
  它自带较短超时，撞上模型冷启动就失败并静默降级成「不翻译」；
  而答案那次调用因为模型已经装好了反而很快，于是表面看就是「库里没证据、而且答得快」。

客户端（另开一个窗口）：

```powershell
& $py scripts\服务_终端客户端.py --fast      # 打字提问
& $py scripts\服务_终端客户端.py --demo      # 第一部分演示台本（8 步）
& $py scripts\服务_终端客户端.py --demo2     # 第二部分演示台本（7 步，约 24 秒）
```

⚠ **Windows 上用 `curl.exe` 传中文 JSON 请求体，只有 `-d "@文件"` 可靠**：
三种内联写法全部失败，`Invoke-RestMethod` 即使显式 UTF8 也把中文写成乱码
（[工程笔记 一·11](工程笔记.md)）。

## 三、验证部署

```powershell
& $py scripts\服务_验证.py            # 224 项离线，约 4 秒，不需要 Ollama、不需要向量库
& $py scripts\服务_验证.py --live     # 追加 5 项真实端到端（真起 uvicorn + 真模型），约 5 分钟
& $py scripts\校验交付包.py           # 11 个交付包的完整性
```

全部闸门（回归用，任一项红了就停）：

| 闸门 | 项数 | 耗时 | 依赖 |
|---|---|---|---|
| `服务_验证.py` | 224（`--live` 229） | 4 s | 无 |
| `约束_验证.py` | 99 | 3 s | 无 |
| `评估_验证.py` | 66 | 12 s | 无 |
| `生成_上下文组装_验证.py` | 58（`--live` 65） | 7 s | **需 Ollama 模型**（分词器从 GGUF 重建）；`--live` 另需 65 GB 库 |
| `检索_多路检索_验证.py --bm25 <索引目录>` | 25 | 37 s | 向量库 + BM25 索引 |
| `golden_跑测.py --assert-baseline` | 14 | 秒级 | **需 `data/golden/` 跑测明细**（不随仓库分发） |
| `校验交付包.py` | 11 个包 | 秒级 | 无 |

⚠ **裸 clone 上可直接跑的是前三道（224 / 99 / 66），其余四道需要本地数据或模型。**
这四道不是坏的，是它们要的东西（Ollama 模型、65 GB 向量库、`data/golden/` 明细）
本来就不随仓库分发——重建步骤见本文第一节。

⚠ **验证报告有防降级保护**：新一轮项数更少、或旧报告里有 `--live` 实测而这轮没有，
都会**拒绝覆盖**（要覆盖得显式 `--force-report`）。报告是交付材料，被弱运行冲掉不可逆——
这个坑变形出现过六次，见 [工程笔记 二·8](工程笔记.md)。

⚠ 跑闸门本身会把「时间：…」写进报告，于是 `校验交付包.py` 会报「包内与 `report_data`
不是同一版」。**这是闸门自己踩出来的脚印，不是回归**——确认差异只在时间戳后，
把报告恢复成冻结版即可。

## 五、不走服务的两种用法

**① 直接在进程里调整条链**：

```python
import importlib.util
spec = importlib.util.spec_from_file_location("gp", r"E:\rag\scripts\生成_流水线.py")
gp = importlib.util.module_from_spec(spec); spec.loader.exec_module(gp)

pipe = gp.MedicalGenerationPipeline(retriever=retr)   # 离线时不传 retriever，改传 retrieved_docs
res  = pipe.generate(q, top_k=10, evaluate=True, review=True)
res["answer"]              # 带 [S#] 出处 + 参考文献 + 免责声明的最终回答
res["sources"]             # [S#] → PMCID / PMID / 期刊 / 年份 / 章节 / PMC 链接
res["citation_check"]      # used / available / fabricated ← 编造的编号会被揪出来
```

要强约束与生成后校验就把 `MedicalGenerationPipeline` 换成
`约束_受限流水线.py::ConstrainedGenerationPipeline`，接口完全兼容。

**② 只用本地模型，不走 RAG**：准备阶段就跑通的最小可用形态，日常随手一问用它。

```powershell
. .\start_medrag.ps1                       # 起 Ollama + 激活环境（最前面的「点 空格」不能漏）
ollama run qwen3:8b                        # 交互式聊天
& $py scripts\命令行提问.py 他汀类药物的主要副作用是什么
& $py scripts\多轮问答.py                   # 带医学 system prompt + 全程日志，推荐
```

`多轮问答.py` 的可调项在文件顶部「可调区」：`SYSTEM_PROMPT` / `temperature`
（医学问答建议 0.2~0.3）/ `num_ctx` / `THINK`。对话日志写到 `logs/chat_log.jsonl`。

⚠ 中文交互走上面这几条路径，不要在 PowerShell 里手拼 JSON 调 API，中文会乱码。
原因与可靠写法见 [工程笔记 一·11](工程笔记.md)。

## 六、检索器与模型的内存冲突

检索器首次加载 **15.8 GB RSS**，Ollama 装着 `qwen3:8b` 另占约 8 GB。
32 GB 机器**不要同时跑两个加载了检索器的进程**。

绕开的办法是两趟跑法——`--dump-retrieval` 把检索结果固化成快照，
`--from-dump` 从快照跑生成。副产品是重跑生成不用再等 67 秒加载检索器。
golden 评测集用的也是这个套路（趟 1 冻结中译英需要 Ollama，趟 2 只跑检索不需要）。

只想调检索、不要重排时传 `load_reranker=False`。
