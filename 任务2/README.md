## 二、四步的关键数字

**第一步 · 结构分析**（3,028 篇，已独立核验：filelist = tar = parquet 三方一致、无重复、随机 5 篇逐字段与原始 XML 比对吻合）

| 字段 | 缺失率 | 处理 |
|---|---|---|
| pmcid / doi / journal / pub_year / title / body | 0% | 直接可用 |
| abstract | **8.36%** | 不丢弃，置空打标；切块用「标题 + 正文」 |
| pmid | **9.08%** | 用 pmcid 兜底（pmcid 100% 完整且唯一） |

> 途中修了一个真 bug：pandas 3.0 的 `str` dtype 让空字符串没被算进缺失率。

**第二步 · 领域理解**：token 三档 ≤4,182 / 中 / >7,400，各约 1,010 篇；IMRaD 各节覆盖 方法 72% / 结果 71% / 讨论 75% / 结论 63% / 背景 66%；本首包内容偏分子生物学与基因组学，纯临床偏少。

**第三步 · 长度量化**：99.24% 超 512。切块数估算（3,028 篇样本）：`512/64` ≈ 4.36 万块、`384/64` ≈ 6.05 万、`256/32` ≈ 8.62 万。

**第四步 · 分割策略**：17,350 个顶层章节，token 中位 648，**54.4% 仍超 512**——所以"只按章节切"不够，必须有递归兜底。模拟 `512/64` 得 51,292 块（16.9 块/篇），其中 45.6% 的章节能整段成块，9,446 个章节需要递归再切。

---

## 三、为什么是「章节感知 + 递归兜底」

- **整体不分割**：99.24% 的文档超 512 token，直接排除。
- **纯滑动窗口**：简单，但会把「Methods 的一句」和「Results 的一句」缝进同一块，检索时语义混杂，且丢掉章节这一层元数据。
- **纯按章节**：语义最干净，但 **54.4% 的章节自己就超 512**，装不进嵌入模型。
- **→ 两层**：章节 ≤512 整段成块（保住语义边界）；>512 的用递归分割器再切；完全无章节结构的整篇走递归。每块挂 **pmcid/pmid（溯源）、journal/pub_year（过滤）、section（章节）**。

## 五、⚠ 本阶段的设计，后来有两处被实测改掉了

读这份报告时要知道：它是**设计文档**，落地时有两处出入，以后面阶段的 README 为准。

| 本阶段的设计 | 实际落地 | 原因 |
|---|---|---|
| 嵌入模型选 **bge-m3**（多语言、上限 8192） | 阶段四改用 **`BAAI/bge-base-en-v1.5`**（768 维，英文专用） | 语料是纯英文 PubMed，英文专用模型更贴；3080 上更快更省显存（见 `任务4/README.md`） |
| 用 LangChain 的 `RecursiveCharacterTextSplitter` 做递归兜底 | 阶段三自研 `smart_split` | 该分割器在**无换行的连续正文**上 overlap 会塌成 0（见 `任务3/README.md`） |

另外，切块按 bge-m3(XLM-R) 分词器计长、embedding 用 bge-base(BERT) 分词器，导致约 **4.3%** 的块超 512 BERT token 被截尾——已知小尾巴，记录在 `任务4/README.md`。

## 六、已知局限

1. **样本只有 3,028 篇**（baseline 首包，2003–2024 年，偏 PLoS/BMC 系）——全量是 400 万篇，本阶段的分布结论是**样本级**的，不能当全量事实用。
2. **内容画像偏分子生物学/基因组学**，纯临床文献偏少；这会影响后续检索在临床类问题上的表现。
3. **chunk 数估算是按公式外推的**，不是真切出来的；阶段三实际全量切出 **9,243 万块**。
