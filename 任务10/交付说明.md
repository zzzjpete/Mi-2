### 关于错误码的两条刻意设计（常见疑问）

1. **拒答不是错误。** 证据不足时返回带固定拒答短语的结构化回答，走 **HTTP 200 / code 0**，
   只在 `data.refused` 标一位。把"守住知识库边界"做成 4xx，等于让阶段九一整个阶段的成果
   在接口层被表达成一次失败。拒答率单独在 `/qa/stats` 统计。
2. **未知异常不伪装成已知码。** 只对能确定含义的给具体码，其余一律 **5001**，
   日志留全栈、响应体只给一句话——把未知异常塞进一个看起来正常的 4xxx，
   会让线上真正的 bug 藏起来。

## 如实说明的局限

1. **默认走快照检索模式**（阶段七固化的 4 组真实检索结果），真检索要 `--mode live`
   （需 65GB 向量库 + 15.8GB 内存）。⚠ live 模式问中文**必须加 `--translate llm`**，
   否则默认词典会把词表外的病名药名整词丢弃——详见 README 第十四节。
2. **鉴权是静态 API Key、限流是单进程内存计数**，够单机离线场景用，多副本部署要换。
3. **客户端断开后生成不会立刻停**：已发给 Ollama 的那一段要跑完。
4. **①③两段不流式**，等待期只有 `stage` 事件与心跳。
5. **会话管理是"够用"版本**，完整模块属于第二部分。路由只依赖
   `ensure / history / append_turn` 三个方法，换实现不用动接口层。
6. **端到端样本量小**：真实实测只跑了 3 个问题 × 2 条路径，**结论看方向与量级**。
