## 第 1 段 · 任务书第 1 条：骨架 / 错误码 / 异常处理 / 日志 / 健康检查

### 1.1　健康检查（存活与就绪分开）

```powershell
& $py E:\rag\scripts\服务_终端客户端.py --demo
```

> 这一条命令会按任务书顺序自动跑完 8 个场景，约 3 分钟。**下面 1.1~2.5 都是它的步骤**，
> 你只要在旁边讲解。它跑到哪一步，屏幕上会打出「对应任务书：X」。

**说**：健康检查做了两个探针。存活探针 `/health` **绝不碰下游**——探针一旦依赖 Ollama，
Ollama 抖一下就会把好好的服务判死、被容器编排重启。就绪探针 `/health/ready` 才去探
Ollama、存储和检索索引，逐项报状态。

**预期**：`/health` 立刻返回；`/health/ready` 列出 5 个组件，全部 ✓，
其中 `retrieval:live` 显示 BM25 索引路径、`llm:ollama` 显示模型已就绪。

### 1.2　错误码枚举

**说**：21 个错误码分五族——1xxx 参数、2xxx 认证配额、3xxx 资源、4xxx 模型与外部依赖、
5xxx 服务内部。任务书点名的 1001 / 2001 / 3001 / 4001 全在表内，而且**每个都有真实触发路径**，
不是写在文档里好看的。码表本身也是一个接口：`GET /api/v1/errors`。

**预期**：打印「共 21 个码，分 5 族」，然后列出任务书点名的那几个。

### 1.3　统一响应格式

**说**：所有接口**成功和失败是同一个形状**——`code / message / data / detail /
request_id / timestamp / elapsed_ms`，`code == 0` 就是成功。客户端不用为错误单写一套解析。
`request_id` 放在**响应体里**而不是只放响应头，因为出问题时用户复制给你的是屏幕上的 JSON，
不是 F12 里的 header。

**预期**：第 3 步先打印响应外层七个字段，再展开 `data`（答案字数、出处条数、拒答标记、
层 D 合规、引用校验、耗时、模型调用次数）。

### 1.4　全局异常处理 + 参数校验（任务书 1.c 与 2.c 一起演）

**预期**：第 5 步连打 6 个用例，**响应体形状始终不变，只有 code 不同**：

| 用例 | 期望 code |
|---|---|
| query 为纯空白 | **1001** 参数错误 |
| query 超长（1001 字） | **1001**，detail 里写明「当前 1001」 |
| top_k 超出范围（999） | **1003** 参数超出允许范围 |
| 缺必填参数 query | **1002** 缺少必填参数 |
| 访问不存在的路径 | **3001** 资源不存在 |
| 会话不存在 | **3002** 会话不存在或已过期 |

**说**：两个细节值得指出。① `top_k` 越界报的是 **1003 而不是笼统的 1001**——调用方一看就知道
是范围问题不是格式问题。② 空 query 判定是 **strip 之后再判**：`"   "` 能过 pydantic 的
`min_length=1`，不先去空白就漏了。③ 未知异常一律 **5001**，日志留全栈、响应体只给一句话——
把未知异常伪装成某个 4xxx，会让线上真 bug 藏在一个看起来正常的响应里。

> **想单独手敲这四条**（比自动演示更有现场感），另开终端：
> ```powershell
> curl.exe -s -X POST http://127.0.0.1:8000/api/v1/qa/ask -H "Content-Type: application/json" -d "{\"query\":\"   \"}"
> curl.exe -s -X POST http://127.0.0.1:8000/api/v1/qa/ask -H "Content-Type: application/json" -d "{\"query\":\"aspirin\",\"top_k\":999}"
> curl.exe -s -X POST http://127.0.0.1:8000/api/v1/qa/ask -H "Content-Type: application/json" -d "{\"top_k\":5}"
> curl.exe -s http://127.0.0.1:8000/api/v1/sessions/not-exist
> ```
> ⚠ **命令里的 query 一律用英文**。Windows 终端把中文内联进 JSON 会把编码弄坏，
> 服务端收到的是坏 JSON，返回「参数解析失败」而不是你想演示的那个码——
> 这是实测踩过的，不是理论风险。超长那条用英文不好敲，看自动演示里那条即可。

### 1.5　日志

**说**：日志与数据库**两件都做**，因为它们回答的是不同的问题——滚动日志答
"这一次发生了什么"，SQLite 答"这一批总体怎么样"。每行日志开头都带 `request_id`；
同步问答跑在线程池里，`request_id` 用 contextvar 传递，**跨线程池不丢**，验证里有实测。

**可选同屏展示**：`Get-Content E:\rag\logs\service\api.log -Tail 15`

## 第 2 段 · 任务书第 2 条：同步 / 流式 / 会话 / 调用记录

### 2.1　同步接口 + 集成 RAG 流水线

**说**：接的是阶段九那条受约束流水线——四段链加强约束提示层加生成后校验修正。
接口层**没有改动阶段七、九的任何一行**，埋点全靠在外面包一层透明代理。

**预期**：第 3 步 20 秒左右返回，带 6~8 条出处，`拒答=False`、`层D合规=True`、
`引用校验 fabricated=[]`（没有编造的编号）。

### 2.2　同一个 request_id 三处一致 ← **这一步值得停久一点**

**说**：这是"记录请求ID用于后续统计"这条要求的落地证据。同一个 ID 在**响应体、SQLite、
日志**三个地方都能查到，而且字段对得上——耗时、状态、token、拒答、合规。

**预期**：第 4 步先打印上一步响应体里的 `request_id`，再用它去库里查回同一条记录。

### 2.3　流式接口

**说**：SSE 七种事件。**最有信息的一格是"出处比第一个答案字先到"**——
在真检索模式下，出处清单约 10 秒到，第一个答案字约 16 秒到，中间差 6 秒。
流式在这个系统里的价值不是逐字打印好看，是**把等待期填上真实信息**：
用户在模型还没开口时就已经看到"我将依据这几篇文献作答"，并且可以点开 PMCID 去核对。

**预期**：第 6 步先刷出出处清单，再逐字流出答案，最后打印各事件首次出现的时刻。

### 2.4　会话管理：传 session_id 关联历史

**说**：历史**只用来把追问改写成可独立检索的问题**，一个字都不进证据区。
"它有哪些局限？"这句话拿去检索全库 399.8 万块英文文献只会召回噪声；改写成
"CRISPR-Cas9 的脱靶效应检测方法有哪些局限？"才检索得到。
⚠ 反过来说，**把上一轮问答原文拼进上下文是危险的**——那等于给模型一段没有出处的事实材料，
它会把自己上一轮说过的话当成证据。

**预期**：第 7 步打印原始问题、改写后检索式、带入历史轮数、会话里已存几条消息。

### 2.5　调用记录分页与聚合统计

**说**：分页字段是服务端算好的——`total / page / page_size / pages / has_next / has_prev`，
客户端不用自己算。聚合给的是成功率、拒答率、层 D 合规率、p50/p95 耗时、token 用量。

**预期**：第 8 步打印分页字段 + 最近 5 条记录 + 聚合数字，
最后是「演示完毕 —— 任务书要求覆盖情况」，逐条打勾。

## 第 3 段 · 真实问答演示（手打，展示系统真的能用）

```powershell
& $py E:\rag\scripts\服务_终端客户端.py --fast
```

> ⚠ **必须加 `--fast`**。不加会走完整四段链，真检索模式下一个问题 60~90 秒，镜头前全是空等。
> `--fast` 只跑"起草答案"一段，约 25~37 秒。

**下面 4 个问题都已在当前配置下实测过**，逐字复制，不要临场改词。

### 问题 1（26.8 秒，7 条出处，层 D 合规）

```
法布里病有哪些酶替代治疗药物？证据如何？
```

**说**：这道题是阶段一压测裸模型时留下的错题之一——当时它把罕见病药的品牌名张冠李戴。
现在答出 agalsidase alfa、agalsidase beta 和 migalastat，并且区分了酶替代疗法与口服伴侣蛋白。
**每一句后面都有 [S#]**，对应下面参考文献里的真实 PMCID。

**建议动作**：**点开一个 PMCID 链接**（`https://www.ncbi.nlm.nih.gov/pmc/articles/PMC.../`），
证明文献是真的、能打开。这一下比任何指标都有说服力。

**顺带指出**：屏幕上会先打出一行 `🔍 检索式：Enzyme replacement therapy drugs for Fabry
disease...` —— 这是系统把中文问题理解成的英文检索式。它比第一个答案字早约 9 秒出现，
**理解错了当场就能看出来**，不用等三十秒后靠一句"无法回答"去猜。

### 问题 2（26.5 秒，7 条出处，层 D 合规）

```
二甲双胍对心血管疾病有何影响？
```

**说**：常见病常见药，检索到的是二甲双胍心血管结局、心肌再灌注损伤、左室质量的研究，
而且**如实指出了争议**——非糖尿病患者中的心血管保护作用仍有争论。
不是把文献里所有说法揉成一个乐观结论。

### 问题 3（37.0 秒，8 条出处，层 D 合规）

```
免疫治疗对肺癌的疗效和安全性如何？
```

**说**：一个问题同时问疗效和安全性，答案两边都覆盖到了，并给出了具体数字
（非鳞状 NSCLC 五年总生存率 19.3%）——**数字也带出处**，这是阶段九"数字必须可溯源"
那条约束在起作用。

### 问题 4 ← **全片最有价值的一分钟**（35.7 秒，正确拒答）

```
药物 XY-9981 治疗肌萎缩侧索硬化的三期临床试验结果是什么？
```

**说**：**这个药名是我编的，世界上没有这个药。** 系统的回答是"根据现有文献无法回答此问题"，
同时如实指出：文献里提到的 ALS 治疗药物是 riluzole 和 edaravone，但它们延长生存的效果有限。

**这就是整个项目要解决的问题**——裸模型面对这种问题会顺着编一个试验名、编几个数字出来，
而且编得很像真的。这里它**不知道就说不知道，并且给出真实存在的替代信息**。
拒答不是失败，是这个系统最重要的能力。

> **可选加分项**（想多演一道就用它，注意会出现黄色告警）：
> ```
> 帕博利珠单抗治疗非小细胞肺癌有哪些随机对照试验证据？
> ```
> 它能答出 KEYNOTE-010 / KEYNOTE-024 / KEYNOTE-671，但客户端会打出一行黄字
> `⚠ 层D 判定不合规：citation.missing、terminology.missing_expansion`。
> **这时候不要慌，这是加分项**：说明系统不只是产出答案，还会**给自己的答案打分并如实报出来**
> ——它检出了 5 个事实句里有 3 句没挂出处、PD-L1 这个缩写首次出现没给全称。
> 一个不会指出自己问题的系统，才是不能用的系统。

## 第 3.5 段 · 任务书第二部分：运营统计 / 文档管理 / 配置（新增，约 2 分钟）

> 全部是**毫秒级**返回的接口，录起来快。都在另一个窗口用 `curl.exe` 敲。
> 前提：已经跑过一次 `服务_文档目录.py --build`（45 秒，见 [`部署文档.md`](部署文档.md)）。

### 3.5.1　运营统计：调用侧 + 知识库侧

```powershell
curl.exe -s http://127.0.0.1:8000/api/v1/qa/stats
```

**说**：上半段是刚才那几次问答的**调用统计**——次数、平均耗时、p50/p95、成功率、
拒答率、层 D 合规率。下半段 `index` 是**知识库统计**：文档总数、块数、索引占盘 68.9 GB、
增量更新次数、三个建库时间。

**这里要停一下讲两句**（全片信息密度最高的地方之一）：

1. **`total_documents` 是 2,274,167，但它旁边跟着一句 `documents_note`**——
   口径是"被抽中至少一块的文献数"。4M 索引是按**块**抽样的，每篇平均只有 1.76 块入库
   （原文平均 28.6 块）。**不说这句，这个数会被读成"库里有 227 万篇完整文献"。**
2. **`incremental_updates` 是 0，这是如实报的**，不是没做：语料是 2026-06-18 的冻结快照、
   一次全量构建，没有增量更新机制。旁边的 `incremental_updates_note` 写着这件事。

### 3.5.2　为什么这几个数是"启动时读一次"

**说**（不用敲命令，一句话带过）：这三个数**不能现算**。实测在 Chroma 上
`count(distinct pmcid)` 要 **221 秒**，而且第一次带过滤的查询会把进程内存顶到 **13.7 GB**——
真放上去，一个毫秒级的统计接口会拖垮整个服务。所以是离线建好目录、启动时读一份 JSON。

### 3.5.3　文档管理：列表（游标分页）+ 按 id 查

```powershell
curl.exe -s "http://127.0.0.1:8000/api/v1/documents?journal=Nature&pub_year=2021&limit=2"
curl.exe -s http://127.0.0.1:8000/api/v1/documents/PMC212698
curl.exe -s http://127.0.0.1:8000/api/v1/documents/PMC999999
```

**说**：
- 第一条：按期刊 + 年份过滤，**1 毫秒**返回；`next_cursor` 是翻页用的游标。
  **没有 page 参数**——227 万行上按页码深翻要扫掉前面所有行，所以用游标。
- 第二条：单篇详情。注意 `total_chunks: 36` 与 `indexed_chunks: 2` 是**两个数**：
  前者是原文切了多少块，后者是真正进了向量库的条数。只给前者会让人以为库里有全文。
- 第三条：不存在 → **3001 / HTTP 404**，而且 `detail.hint` 特意说明"不在本地 4M 抽样索引里
  ≠ PMC 上没有这篇"。

### 3.5.4　健康检查现在有 8 个组件（任务书点名的三样都在）

```powershell
curl.exe -s http://127.0.0.1:8000/health/ready
```

**说**：`llm:ollama`（LLM）、`vector_db`（向量库）、`call_log_db` 与 `session_db`（数据库）——
任务书要的三样都在，另外还有检索索引、文献目录、日志。
**`vector_db` 只 stat 不打开**：打开一个 4M 集合要 22 秒 + 13.7 GB，就绪探针绝不能付这笔钱。

### 3.5.5　配置：命令行 > 环境变量 > .env > 默认值

```powershell
curl.exe -s http://127.0.0.1:8000/api/v1/config
```

## 万一出状况

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 答案开头写"根据现有文献无法回答" | 问了台本外的问题，证据不足 | **照实说**：这是系统守住知识库边界，不是故障。换回台本里的问题 |
| 黄字 `⚠ 层D 判定不合规` | 层 D 检出自己答案的问题 | 按上面"可选加分项"那段说法讲，这是特性不是 bug |
| 首字等了很久 | 真检索 + 整句翻译，正常 20~40 秒 | 利用等待期讲"出处已经先到了" |
| 输入 `--mode live` 之类被当成问题 | 那是**起服务时**的参数 | 客户端会拦下 `-` 开头的输入并提示 |
| 服务没反应 | 检索器可能还在加载（约 70 秒） | 等 `/health/ready` 返回 `pipeline_loaded: true` |

> 最后提醒：**录屏前不要临时改问题**。这 4 个问题是在当前配置（live 真检索 +
> qwen3 整句翻译 + 拆三态后的约束提示词）下逐个实测过的，换一个词都可能落到证据不足的一侧。
